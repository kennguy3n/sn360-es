# SN360-ES Test Corpus

The evaluation corpus is the canonical, deterministic set of synthetic
test emails used to validate the SN360-ES detection pipeline end to
end. It is generated by [`scripts/corpus_generator/`](corpus_generator/)
and conforms to [`scripts/corpus_schema.json`](corpus_schema.json).

This document describes the data model, the model deployments the
corpus is wired to, the directory layout, and the day-to-day commands
for generating and validating the corpus.

## Models

The corpus speaks to exactly two model deployments. Do not substitute
either; the corpus is reproducible only against this pipeline.

### Tier 1 — XLM-RoBERTa encoder

- **Source**: [`deployments/encoder/`](../deployments/encoder/),
  FastAPI + ONNX Runtime image
  `ghcr.io/kennguy3n/sn360-es-encoder:latest`.
- **Endpoint**: `POST /predict` (single) and `POST /predict/batch`
  (`internal/service/tier1/encoder.go`).
- **Local port**: 8080.
- **Score thresholds**: pass < 20, escalate 20–60, flag > 60
  (`internal/service/tier1/config.go DefaultThresholds`).
- **Boot**: `docker build -f deployments/encoder/Dockerfile -t sn360-es-encoder . && docker run -p 8080:8080 sn360-es-encoder`.

### Tier 2 — Ternary-Bonsai-8B-Q2_0 LLM

- **Source**: [`deployments/llm/`](../deployments/llm/), multi-stage
  Dockerfile that compiles
  <https://github.com/kennguy3n/llama.cpp> from source. Image
  `ghcr.io/kennguy3n/sn360-es-llm:latest`.
- **Model**: Ternary-Bonsai-8B-Q2_0 GGUF from
  <https://huggingface.co/prism-ml/Ternary-Bonsai-8B-gguf/blob/main/Ternary-Bonsai-8B-Q2_0.gguf>.
- **Endpoint**: OpenAI-compatible `POST /v1/chat/completions` (served
  by the `llama-server` binary built from kennguy3n/llama.cpp).
- **Local port**: 9000.
- **Boot**: `make docker-build-llm && make docker-run-llm`. The init
  container in [`deployments/llm/deployment.yaml`](../deployments/llm/deployment.yaml)
  invokes `download-model.sh` so the GGUF is never baked into the
  image.

No other LLM provider, runtime, or upstream `ggerganov/llama.cpp`
build is supported by this corpus. Alternative model providers are
not supported.

## Pipeline mapping

Every test email declares the expected flow it should produce.

| Case | `tier0_bypass` | `expected_tier1_verdict` | `expected_tier2_needed` | Typical tier |
|------|---------------:|--------------------------|-------------------------|--------------|
| Benign + internal/vendor/newsletter | `true` | `skip` | `false` | Trusted |
| Benign + external | `false` | `pass` | `false` | Trusted / Informational |
| Threat + easy | `false` | `flag` | `true` | Blocked |
| Threat + medium | `false` | `flag` | `true` | Blocked / HighRisk |
| Threat + hard | `false` | `escalate` | `true` | HighRisk / Warning |

These transitions are encoded once, in
[`generator.go`](corpus_generator/generator.go) (`tier1VerdictFor`,
`tier2NeededFor`, `tierAndScoreFor`). The validator in
[`validator.go`](corpus_generator/validator.go) checks every row
against the same contract so the corpus can never drift.

## Schema

The canonical JSON schema is
[`scripts/corpus_schema.json`](corpus_schema.json) (draft 2020-12).
Highlights:

- **`category`** — one of 16 values, mirroring
  `internal/constant/categories.go AllCategories`.
- **`expected_tier`** — one of 6 values, mirroring
  `internal/constant/tiers.go AllTiers`.
- **`expected_score_range`** — `[low, high]`, must sit inside the
  tier band defined by `internal/config/config.go ScoreThresholds`
  defaults: Blocked 85–100, HighRisk 70–84, Warning 50–69, Caution
  30–49, Informational 15–29, Trusted 0–14.
- **`expected_tier1_verdict`** — one of `pass`, `escalate`, `flag`,
  `skip`.
- **`expected_tier2_categories`** — non-empty when
  `expected_tier2_needed` is `true` and the email is a threat.
- **`payload`** — `from`, `from_display`, `to`, `subject`,
  `body_text`, `body_html`, `headers`, `attachments`.

## Distribution targets

with category-level threat / benign splits derived from
`Category.IsBenign()` / `Category.IsHighSeverity()`:

| LIKELY_PHISHING            | 375 | 95  | 470 |
| BEC_IMPERSONATION          | 375 | 95  | 470 |

| SUSPICIOUS_URL             | 282 | 188 | 470 |

The default difficulty mix is 33% easy / 34% medium / 33% hard. The
default locale mix is 80% English with the remaining 20% spread
evenly across `th`, `ja`, `ko`, `zh`, and `vi`.

## Directory layout

```
scripts/
├── corpus_generator/        # Go CLI (see corpus_generator/README.md)
├── corpus_schema.json       # JSON Schema for individual emails
├── corpus/
│   ├── evaluation/          # Generated per-category JSON files (gitignored)
│   │   └── sample.json      # ~10 emails per category, checked in for CI
│   └── loadtest/            # Bulk fixtures for stress / scale runs
└── CORPUS.md                # This file
```

Generated files in `evaluation/` are gitignored apart from
`sample.json`. The full corpus is regenerated on demand with `make
generate-corpus`.

## Workflow

### Generate

```bash
make generate-corpus                # deterministic, template-only
make generate-corpus-llm            # adds Ternary-Bonsai-8B-assisted variants
```

The LLM-assisted run requires the Tier 2 service from
[`deployments/llm/`](../deployments/llm/) running locally on port 9000.

### Validate the corpus on disk

```bash
make validate-corpus
```

Checks schema completeness, category / tier / score consistency, the
pipeline contract (`tier0_bypass → skip`, `pass → no tier 2`, etc.),
locale and difficulty distribution, and near-duplicate detection via
Jaccard on word trigrams.

### Validate the real models against the corpus

```bash
# Boot encoder + LLM locally first:
docker run -p 8080:8080 sn360-es-encoder
make docker-build-llm && make docker-run-llm

make validate-corpus-models
```

This pushes every non-bypassed email through the Tier 1 encoder and,
when `expected_tier2_needed`, through Ternary-Bonsai-8B via
kennguy3n/llama.cpp. The report shows per-category agreement, the
list of disagreeing `test_id`s, and overall accuracy.

## Determinism

The generator is byte-deterministic given a `--seed`. Two CI runs
with the same seed will produce identical bytes on disk. See
[`scripts/corpus_generator/README.md`](corpus_generator/README.md)
for the list of changes that invalidate that guarantee.
